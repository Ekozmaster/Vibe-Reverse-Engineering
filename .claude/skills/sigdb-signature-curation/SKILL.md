# Curate sigdb sources so names transfer only where code is identical

Import only names for code that compiles identically in other binaries: statically linked library code (MSVC CRT/STL, Havok, Gamebryo, RenderWare, zlib). Game-specific names mislabel other games and slow every scan, so keep them out of the shared DB.

- Check the source's target before reading any external symbol source (PDB, decomp repo, symbol list). Its CPU, OS and compiler must match the target binary: a PowerPC Xbox 360 PDB cannot label x86 PE code, and Linux ELF symbols or a rebuild with a different compiler (VC6/VC7.1 vs retail) only transfer after byte-verified matching.
- Filter before building: drop functions under 16 bytes (generic first-32-byte patterns). `sigdb import-pat` (FLIRT `.pat` files) and `sigdb build` (binary + CSV map) both do this. A byte prefix that maps to more than one name is kept under each name, and matching returns nothing for it on a binary whose toolchain allows more than one of those rows; different keys that score equally under different names also match nothing, and the structural tier does not break either tie. Give `build` a `size` column when the map has sizes (decomp `units.json`, linker maps): the estimate runs past functions that end in a jump, and a short sig sized by the estimate matches only functions the estimate sizes alike.
- Resolve export and map addresses that land on incremental-link thunks (`E9 rel32` tables) to the function body before building; a thunk's prefix is all wildcards and is skipped as too few fixed bytes.
- Keep provenance: prefer tagged library subsets (for example HAVOK_LIB, GAMEBRYO_LIB) over GUESS, COMMUNITY, or XBOX_* names. Record compiler and source per sig.
- Label every sig with its exact MSVC version (`msvc2008`, `msvc6.0`, `msvc2003_2005`); `msvc7.10` is read as 7.1. Matching skips sigs whose versions are absent from the C/C++ compiler entries of the binary's Rich header; a bare `msvc` label is never skipped, so it scans VC6 games against VS2008 code. `build` and `import-pat` refuse a label that starts with `msvc` and names no version (`msvc_2008`, `MSVC2008`).
- Prefer sources with a FLIRT CRC16 (`.pat` lines): matching rejects a sig whose CRC over the bytes after the prefix fails. Sigs that fit in the 32-byte prefix carry no CRC; one that pins nothing after its function's end matches only a function that ends where the sig does (the first return, leaving jump, or call followed by `int3` that no earlier branch passes, or the size estimate).
- Bootstrap writes every sig match into kb.h with no confidence floor. `scan` already drops a name that is the best match at more than one address; tiny generic functions (MFC `CRect` constructors in a non-MFC game) can still be named wrongly.
- The byte tier wildcards only E8/E9 rel32 operands, including one cut off at the end of the 32-byte prefix. Absolute addresses (globals, vtables, IAT calls) are not wildcarded, so names carry only to identically laid-out binaries.
- Layout-dependence check must cover every absolute operand, including indexed ones: `jmp dword ptr [eax*4 + abs32]` (switch tables) and `mov al, [eax + abs32]` are not wildcarded by a check that only looks at `mem.index == 0`. Such a CRC16 then rejects the same function in any other binary, and `match_bytes` rejects on mismatch rather than scoring low. Test any change with an `FF 24 85 <abs32>` case.
- A row is one `(pattern, mask, crc_len, crc16)` key under one name and one compiler label, and `already_in_db` counts only that exact row. No import deletes a held row, so the order of imports does not change the database and repeating one adds nothing.
- Validate before publishing: build from a subset, scan the source exe (expect near 100%), scan a second game on the same library version, and score the hits by hand.
- Build and test candidates on copies. `scan` and `identify` open a DB read-only and refuse a file that lacks any of the four tables (`schema_version`, `byte_sigs`, `structural_sigs`, `compiler_fingerprints`), as `build` and `import-pat` do for a file that is not empty; `pull` removes a leftover `-wal`/`-shm` before it replaces the DB; the first write (`build`, `import-pat`) switches it to WAL and migrates a schema-1 DB in place, so copy `retools/data/signatures.db` first, scan the same binaries with the old copy and the candidate, diff the hits, and confirm `git status retools/data/` is clean.
- After editing `retools/sigdb.py`, run `python -m pytest tests/test_sigdb.py -q` and the CI lint: `ruff check --select F --ignore F401,F541,F841 --exclude tools,rtx_remix_tools/dx/remix-comp-proxy/deps .`

- Structural signatures carry the shape version of `cfg.py` they were built by and match only under the current one (`cfg.SHAPE_VERSION`). `build` and `scan` print how many rows of a DB are in an older shape. Those rows can only be rebuilt from the source binary with `sigdb build`; a function-address map alone is not enough. The `devilution` and `cmr2_decomp` structural rows of the published DB are in that state. Raise `SHAPE_VERSION` in the same change as any edit to how `cfg.py` forms blocks or edges.
- Publish a database that older code refuses (a new schema) to a named branch of the Hugging Face signature repo, never to `main`. Create the branch from `main`, commit there, then confirm `main`'s sha is unchanged and that `resolve/<branch>/signatures.db` serves the new size. The PR must say the file moves to `main` at merge.
- Load `HF_TOKEN` from the repo `.env` with `set -a; . ./.env; set +a` before the upload, and never echo it.

Keep measured facts about a candidate source under `patches/_research/`, not in a tracked file.
